## 原始型別與宣告 核心整理

Go 語言的原始型別（Predeclared Types）雖然與其他語言相似，但在使用上存在著微妙但關鍵的差異，掌握這些差異是編寫慣用（Idiomatic）Go 程式碼的基礎。

### 內建型別的通用特性

#### 1. 零值（The Zero Value）

Go 語言確保所有已宣告但未明確賦值的變數都會被賦予一個明確的「零值」（Zero Value）。這種設計消除了 C/C++ 等語言中常見的潛在錯誤源，提高了程式碼的清晰度。

| 型別 (Type) | 零值 (Zero Value) | 說明 |
| :--- | :--- | :--- |
| `bool` | `false` | |
| 數值型別（整數、浮點數、複數） | `0` | |
| `string` | `""` (空字串) | |
| 指標、interface、Slice、Map、Channel | `nil` | |

#### 2. 字面量與非型別特性（Literals and Untyped Nature）

字面量（Literals）是直接寫出的數值、字元或字串。

* **數值字面量：**
  * 整數(integer literal)預設為十進制，可使用前綴 `0b`（二進制）、`0o`（八進制）、`0x`（十六進制）指定基數。
  * 浮點數(floating-point literal)支援小數點或指數符號 `e` / `p`。
  * Go 允許在數字中使用底線 `_` 來提高可讀性（例如 `1_234`），但不能置於開頭或結尾，也不能連續使用。
* **字元與字串字面量：**
  * Rune(rune literal) 字面量（字元）：使用**單引號** `'a'`，代表單一 Unicode 碼點。
  * 字串字面量：
    * **解釋型字串：** 使用**雙引號** `"Hello\nWorld"`，支援跳脫字元（如 `\n`）。單引號和雙引號不能互換。
    * **原始型字串：** 使用**反引號** `` `...` ``，內容將按原樣呈現，不解析跳脫字元，常用於多行字串。

* **非型別特性：** Go 中的字面量是「非型別」（untyped）的。這賦予了它們彈性，允許在不需顯式轉換的情況下與多種相容的型別（如 `int` 或 `float64`）的變數進行互動。然而，如果字面量的值超過目標變數的容量限制（例如將 `1000` 賦值給 `byte`），則會引發編譯錯誤。在沒有上下文指定型別時，非型別常數會依賴預設型別（例如整數預設為 `int`）。

>**工程建議：** 應避免使用單獨前導零來表示八進制，以防混淆。

### 數值與布林型別（Numeric and Boolean Types）

#### 1. 布林值（Booleans）

* `bool` 型別僅有 `true` 和 `false` 兩個值。
* **無真值性（No Truthiness）：** Go 不允許將非零數值或非空字串等隱式解釋為布林值 `true`。必須使用明確的比較運算子來獲得布林結果（例如 `if x != 0`）。

#### 2. 整數型別（Integer Types）

* Go 提供多種帶符號（`int8` 到 `int64`）和無符號（`uint8` 到 `uint64`）的整數型別。
* **特殊型別名稱：**
  * `byte` 是 `uint8` 的別名。
  * `rune` 是 `int32` 的別名，用於表示 Unicode 碼點（字元）。
  * `int` 和 `uint` 的大小取決於 CPU 架構（多數 64 位元系統上為 64 位元）。
* **使用建議：** 在絕大多數情況下，應使用無明確大小限制的 **`int`** 型別，除非程式碼需要與特定大小的二進制格式或網路協定整合。

| Type name | Value range |
|---|---|
|int8 | –128 to 127 |
|int16|–32768 to 32767|
|int32 |–2147483648 to 2147483647|
|int64|–9223372036854775808 to 9223372036854775807|
|uint8| 0 to 255|
|uint16|0 to 65535|
|uint32| 0 to 4294967295|
|uint64|0 to 18446744073709551615|

#### 3. 浮點數型別（Floating Point Types）

* Go 提供 `float32` 和 `float64`。
* **使用建議：** 除非有相容性需求，否則建議使用 **`float64`**，因為它是浮點數常數的預設型別，且精度更高。
* **重要警告：** 浮點數是近似值，不應在需要精確十進制表達的場合（例如處理金錢）中使用。比較兩個浮點數時，不應直接使用 `==`，而應檢查它們的差異是否在可接受的誤差範圍內（epsilon）。

>像整數類型一樣，浮點類型的零值是 0。

### 明確的型別轉換（Explicit Type Conversion）

Go 語言的一大特色是它**不支援自動型別提升（Automatic Type Promotion）**。為了保證程式碼的意圖清晰和可讀性，開發者必須使用顯式轉換來處理不同型別的數值運算。

**程式碼範例：**

```go
// make run
package main

import "fmt"

func main() {
    var total int = 50
    var avg float64 = 7.5

    // 錯誤：Go 不允許直接混合不同數值型別運算
    // sum := total + avg 

    // 正確：必須顯式轉換型別
    // 將 int 轉為 float64 才能相加
    resultFloat := float64(total) + avg 
    
    // 將 float64 轉為 int 相加（會截斷小數部分）
    resultInt := total + int(avg) // avg 7.5 變成 7

    fmt.Println(resultFloat) // 57.5
    fmt.Println(resultInt)   // 57
    
    // 嚴格性：不能將數值隱式視為布林值（無真值性）
    // if total { ... } // 錯誤：無法將 int 當作 bool
    if total != 0 {
        fmt.Println("Total is non-zero.") 
    }
}
```

### 變數宣告與常數（Declarations and Constants）

Go 提供了多種變數宣告方式，每種方式都傳達了不同的意圖，這要求開發者做出明確的選擇。

#### 1. `var` 與 短宣告 `:=` 的比較（`var` Versus `:=`）

| 宣告方式 | 語法範例 | 說明 |
| :--- | :--- | :--- |
| **完整宣告** | `var x int = 10` | 最明確，適用於型別和值都指定時。 |
| **省略型別** | `var x = 10` | 依賴賦值來推斷型別（例如 `int`）。 |
| **零值宣告** | `var x int` | 明確宣告變數，並賦予零值。**（推薦用於零值初始化）**。 |
| **短宣告** | `x := 10` | 只能在**函式內部**使用，宣告並同時賦值，依賴值進行型別推斷。|

**慣用實踐建議：**

1. 在函式內部，除非是零值初始化或型別不符，否則優先使用 `:=`。
2. 若常數的預設型別與期望型別不一致，應使用冗長的 `var` 形式並指定型別，而非使用型別轉換搭配 `:=` (例如：`var x byte = 20`)。
3. `:=` 允許同時宣告新變數並重新賦值給舊變數，這可能導致**變數遮蔽（Shadowing）**的潛在問題，需特別留意。

#### 2. 常數宣告（Using `const`）

* `const` 用於給編譯時期（Compile Time）可確定的字面量賦予名稱。
* **限制：** 常數的值*必須能在編譯時計算出來*。不能使用函式呼叫的結果（除了少數內建函式如 `len`, `cap` 等）。
* **型別：** 常數可以是**非型別**（更靈活，可與多種相容型別互動）或**型別**（限制其只能直接賦值給特定型別的變數）。

**程式碼範例：**

```go
package main

import "fmt"

const CompileTimeVal = 100 // 非型別常數，可靈活使用

func main() {
    // 1. 函式內常用的短宣告
    x := 5
    s := "Go Language" 

    // 2. 宣告零值：明確使用零值時的最佳寫法
    var counter int // counter = 0

    // 3. 需指定非預設型別時
    var b byte = 255 // 避免使用 b := byte(255)
    
    // 4. 變數遮蔽範例 (Bad Practice!)
    if x > 0 {
        x, y := 20, 30 // 在內部區塊 (Block) 宣告了新的 x 和 y
        fmt.Println("Inner x:", x) // 20
    }
    fmt.Println("Outer x:", x)     // 5 (外部的 x 未被改變)
}
```

### 命名規範與編譯要求（Naming and Compiler Requirements）

#### 1. 命名規範

* **風格：** 應使用 **camelCase**（駝峰式命名，如 `indexCounter`），而非 snake\_case（蛇式命名，如 `index_counter`）。
* **長度與作用域：** 作用域越小，名稱應越短（例如迴圈中的 `i`, `k`, `v`）。在 Package 級別應使用更具描述性的名稱。
* **可匯出性（Exportability）：** 變數或常數名稱的首字母大小寫決定了其是否可被其他套件存取。

#### 2. 編譯時強制要求

* **未使用變數錯誤：** Go 編譯器要求所有已宣告的**區域變數**必須被讀取（使用），否則會引發編譯時錯誤。這項要求有助於保持程式碼的整潔。
  * 變數被賦值但未被讀取的狀況（無效賦值）編譯器不一定捕捉，但可由第三方工具（如 linters）檢測。
* **未使用常數：** 常數不受此限制，因為它們在編譯時確定且沒有副作用，未使用的會被自動消除。
